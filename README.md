# VirtualBox-Based SOC Lab with Wazuh

A hands-on Security Operations Center (SOC) lab built using Oracle VirtualBox, Wazuh SIEM, Ubuntu Server, Windows 10, and Kali Linux.

This project demonstrates how to build a small SOC environment, collect endpoint security events, monitor suspicious activities, develop custom detection rules, and validate security alerts through controlled attack simulations.

## Project Overview

The objective of this project is to simulate a practical SOC environment where security events generated by an endpoint are collected, analyzed, and detected using Wazuh.

The lab uses three virtual machines:

- **Ubuntu Server:** Hosts the Wazuh Manager and Dashboard.
- **Windows 10:** Acts as the monitored endpoint and victim machine.
- **Kali Linux:** Performs controlled security testing and attack simulations.

The environment uses a VirtualBox Host-Only Network to provide isolated communication between the virtual machines.

### Security Monitoring Workflow

1. Kali Linux generates controlled security testing activity.
2. Windows 10 generates security events.
3. The Wazuh Agent forwards collected events to the Wazuh Manager.
4. Wazuh analyzes events using built-in and custom detection rules.
5. Security alerts are displayed through the Wazuh Dashboard.

## Detection Capabilities

The lab implements and validates several security monitoring and detection capabilities.

| Detection | Wazuh Rule ID | Level | Description |
|---|---:|---:|---|
| File Creation (FIM) | 554 | 5 | Detects monitored file creation |
| File Modification (FIM) | 550 | 7 | Detects monitored file modifications |
| Windows Failed Login | 60122 | 5 | Detects failed Windows authentication |
| Repeated Failed Logins | 100100 | 10 | Detects five failed logins from the same source IP within 120 seconds |
| PowerShell Script Block Logging | 100200 | 5 | Detects PowerShell Event ID 4104 |
| Encoded PowerShell Execution | 100300 | 10 | Detects PowerShell execution using `-EncodedCommand` |

**Note:** Wazuh rule levels indicate alert severity, not a direct measurement of attack probability. Detection of encoded commands does not automatically mean that an activity is malicious.

## Custom Detection Engineering

Three custom Wazuh detection rules were implemented.

### Rule 100100 – Repeated Failed Login Detection

- Detects repeated failed Windows login attempts.
- Uses Windows Security Event ID 4625.
- Detects five failed logins from the same source IP within 120 seconds.
- Alert Level: 10.

### Rule 100200 – PowerShell Script Block Logging

- Detects PowerShell Script Block Logging events.
- Uses Windows PowerShell Event ID 4104.
- Uses Wazuh's built-in rule 91802 as the parent rule.
- Alert Level: 5.

### Rule 100300 – Encoded PowerShell Detection

- Detects PowerShell commands executed using `-EncodedCommand`.
- Uses Windows process creation telemetry (Event ID 4688).
- Uses Wazuh's built-in rule 67027 as the parent rule.
- Mapped to MITRE ATT&CK techniques T1059.001 and T1027.
- Alert Level: 10.

## MITRE ATT&CK Mapping

| Technique | Technique ID | Related Detection |
|---|---|---|
| Password Guessing | T1110.001 | Repeated Failed Login |
| PowerShell | T1059.001 | Encoded PowerShell |
| Obfuscated Files or Information | T1027 | Encoded PowerShell |

These mappings describe the relevant adversary techniques associated with the detected behavior. They do not establish that every matching event represents a confirmed attack.

## Installation and Setup

The lab can be reproduced by creating the virtual machines and configuring the required network and Wazuh components.

Recommended setup sequence:

1. Install Oracle VirtualBox.
2. Create a VirtualBox Host-Only Network.
3. Install and configure Ubuntu Server.
4. Install Wazuh Manager and Dashboard.
5. Install Windows 10 and configure the Wazuh Agent.
6. Install Kali Linux.
7. Configure the IP addresses and connectivity.
8. Configure monitoring and detection rules.

Refer to the `documentation/` directory for detailed installation and configuration instructions.

### Network Configuration

Use the following IP address plan for the original lab configuration:

- Wazuh Manager: `192.168.56.104`
- Windows Agent: `192.168.56.103`
- Kali Linux: `192.168.56.102`

Users may need to adjust these addresses according to their own VirtualBox Host-Only Network configuration. Update the corresponding Wazuh agent and manager settings when changing addresses.

## Running Verification Scripts

The repository includes Bash scripts to help verify the Wazuh environment.

Run the scripts on the Ubuntu Wazuh Server.

### 1. Verify Wazuh Manager Status

```bash
chmod +x scripts/verify-wazuh-status.sh
./scripts/verify-wazuh-status.sh
```

### 2. Verify Agent Status

```bash
chmod +x scripts/verify-agent-status.sh
./scripts/verify-agent-status.sh
```

### 3. Search Wazuh Alerts

```bash
chmod +x scripts/search-wazuh-alerts.sh
./scripts/search-wazuh-alerts.sh 100300
```

These scripts require appropriate permissions and, for alert searching, `jq` to be installed.
